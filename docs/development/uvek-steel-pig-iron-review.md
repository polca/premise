# Native pig-iron regionalisation

Use the complete native “Pig iron, at plant” GLO/RER producers as auxiliary blast-furnace suppliers. The exact name/product/kg alias is in the steel YAML, without an IAM technology alias: it is not an additional steel technology or market. The existing shared regionalisation, original-dataset forwarding and consumer-relinking functions remain responsible for the update. Direct-reduction iron, scrap, cast iron and finished steel do not match this alias. Geographic extrapolation, historical technology and native allocation remain screening limitations.

The previously hardcoded production-name filter and validation predicates need a small shared Python bridge to consume this alias. Validation still requires a positive pig-iron input in the consumer's IAM region, and now applies the existing pig-iron energy bounds to qualified native producers too. The RER producer has mass-based light fuel oil omitted by the old energy sum. Its existing exact fuel alias and 42.6 MJ/kg YAML heating value provide the additional energy; no process coefficient, unit, uncertainty, heating value or validation threshold is adjusted. Unknown products, wrong units and negative quantities do not acquire positive energy through this classification.

A real run exposed a separate cache defect. Cloning native pig iron calculated a EUR-to-RER route before the EUR producer was indexed. That route survived creation of the EUR producer and was reused by two European steel consumers. A ten-line generic change at the existing provider-index insertion boundary invalidates cached routes for the newly available local name/product/unit. Other products, units and locations remain untouched. The normal relinker then selects EUR. This cannot be fixed by adding another mapping alias. A synthetic regression fails before the cache correction and passes afterwards; the real trace confirms the route changes from RER to EUR.

Verification so far: 198 focused transformation/steel/validation tests pass; 58 focused existing biomass, cement, heat-consumer and steel tests also pass (groups overlap). A further electricity/fuel-handover regression group passes 54 tests; two licensed electricity checks skip because that test environment has no IAM key. These skipped checks are separate from the real encrypted scenario diagnostic. Documentation reference tables pass their drift check. Ruff passes for the steel and test modules; transformation and validation retain their four pre-existing findings each, with no additional findings. Source-database metadata remains unchanged during preparation. Real encrypted REMIND SSP2-NPi 2050 preparation returns 75 imports and 12,022 base records. The shared steel update then returns 12,511 records with its strict sector checks passing, instead of the previous 26 pig-iron failures. This diagnostic bypasses only the public sector gate; no checks or thresholds are disabled.

Steel remains publicly gated. Full role coverage, exhaustive certification, Brightway export, finite LCIs and combined-sector regression remain separate requirements. Sector-check success does not establish these or source/native impact equivalence. There are no database schema migrations and no Brightpath resource changes in this batch.
