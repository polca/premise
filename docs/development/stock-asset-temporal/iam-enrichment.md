# Consuming reconstructed IAM stock-vintage variables

The `feat/iam-stock-vintage-enrichment` branch adds runtime access to annual
cohort quantities and shares generated by the paired `iam-preprocessor`
`feat/stock-vintage-enrichment` branch. flodym is a preprocessing dependency;
premise reads the prepared numeric arrays without importing it.

## Opt-in interface

Generate the enriched scenario and its report using the preprocessor's
`stock-vintages` command. Keep original stock/capacity inputs until enrichment
has run. The command's integrated filtering/encryption options retain the
namespace and update the report's source/output hashes. Later independent file
transforms require a new matching report.

Place the generated file under an accepted scenario filename, for example
`remind_SSP2-NPi2025.csv`, and supply its directory through premise's normal IAM
file configuration. Renaming preserves the hash. The existing reader retains
`Stock Vintage|v1|<asset-id>|...` rows in `IAMDataCollection.data`; `iam_source_path`
identifies the file on both uncached and cached reads.

```python
iam = scenario["iam data"]
service_record = iam.stock_vintage_weights("passenger-bev", "EUR", 2030)
stock_record = iam.stock_vintage_weights("passenger-bev", "EUR", 2030, basis="stock")
profile = iam.stock_vintage_profile(
    asset_id="passenger-bev", region="EUR", years=range(2022, 2051),
    report_path="stock-vintages-report.json",
    asset_unit="kilogram", service_unit="kilometer",
)
```

Records contain `service_year`, calendar `event_years` and `weights`. The profile
factory always uses service shares for the reviewed common-amortisation route.
Add it to an existing `StockVintageExport` payload with a matching inventory
context and exact caller/supplier bindings. It does not create those bindings,
convert regional GW/counts into an inventory amount, or infer lifecycle roles.
The `asset_unit` and `service_unit` are inventory units and must match the binding.

The consumer checks explicit annual coverage, unitless shares, finite nonnegative
quantities, cohort chronology, sums and stock totals. Zero-stock/service years,
unknown assets or regions, and absent years fail. Shares are neither interpolated
nor normalized at runtime. Cohort dates may precede the IAM scenario-year floor;
they remain in the variable names and physical event calendar.

The profile factory binds the report to the exact plain/encrypted source bytes,
checks model/pathway, and embeds source/report/code hashes, lifetime/initial-state
and utilization assumptions. Existing `StockVintageExport` validation still
checks annual continuity, inventory identities, units and allocation basis.

## Scientific boundaries

The first scenario is SSP2-NPi2025 with passenger BEVs and heavy trucks in EUR,
and PV/CCGT in USA. UK and US-WECC initial observations supply labelled regional
composition proxies. The reviewed horizon is 2022–2050, not automatically 2100.
An IAM technical-life variable is used only under the documented lifetime
interpretation. Initial survivors are conditioned on their observed presence.
Additional operating-stock exits are not physical disposal observations.

Stock-driven and inflow-driven results expose their residuals against the unused
constraint. They are not simultaneous native-stock/production reconstructions.
The service shares remain assumption-dependent even when aggregate IAM service
is reproduced. The original exchange amount and common amortisation stay fixed.

Do not attach a parent asset profile to batteries, inverters, maintenance,
construction scraps, land occupation or disposal indiscriminately. Existing
reviewed lifecycle/component rewrites remain separate. The water-infrastructure
pilot remains based on external observations, with no REMIND forecast claimed.

## Validation and reproduction

`tests/test_iam_stock_vintage.py` covers the real IAM reader, annual lookup,
stock/service differences, malformed data, report binding, source encryption,
cached reads and compatibility with `StockVintageExport`.

`dev/stock_vintage/export_iam_enrichment_fixture.py` uses the actual enriched
REMIND file and the real matrix/datapackage exporter to produce constant- and
varying-background fixtures. The inventories are synthetic and explicitly
labelled. The paired TRAILS checker independently verifies signed quantities,
exact dated pulses and analytical LCI. These checks validate the interface;
they do not claim a new full ecoinvent regional LCA. The earlier complete
licensed pilot evidence remains separate and unchanged.

```console
python dev/stock_vintage/export_iam_enrichment_fixture.py \
  --scenario-dir /path/to/enriched-scenario \
  --report /path/to/enrichment-report.json \
  --output-dir /path/to/new-integration-output
```

The detailed YAML and variable schema live in the preprocessor repository's
`docs/stock-vintages.md`; its `docs/stock-vintage-validation.md` describes the
one-scenario campaign and remaining methodological/data gaps.
