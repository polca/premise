# Steel gas-carrier recognition

The native-volume gas helpers already used by two direct-reduction templates were missing from carrier classification. Their quantities were present, but the shared energy calculation recognised only names containing “natural gas”, reporting zero fuel energy for a helper named “global high-pressure gas supply”.

The fuel YAML now includes the two independently reviewed nominal-36-MJ/m3 helpers as carriers. The existing market-supplier selection is unchanged. Steel passes exact mapped name/product/unit identities to its energy calculation and validator, alongside the existing ecoinvent name recognition. This small shared Python adaptation is needed because a YAML alias alone cannot change the hardcoded name check. No quantities, reference units, LHV factors, thresholds or migration approvals change. Classification uses the non-mutating map builder and does not annotate native suppliers.

Verification: 146 focused steel, mapping and validation tests pass. The exact-product regression rejects a similarly named exchange with a different product. Ruff passes for the modified steel and test modules. A real encrypted REMIND SSP2-NPi 2050 diagnostic prepares 75 imports and 12,022 base records without modifying the source database. The shared update's validation errors decrease from 52 to 26: all gas-energy errors clear; the remaining errors concern native pig-iron supplier recognition/regionalisation. The public steel gate is bypassed only in the private diagnostic process. Steel export and complete sector coverage remain unverified; this is not a claim of operational steel support.
